Les diagrammes UML de mes 9 projets de patterns

Un diagramme de classes par projet de la solution DesignPatternBuilder, dessiné à partir du code : les noms, les visibilités et les signatures sont ceux du C#. La classe Program apparaît comme client.

Trait plein + triangle : hérite

Pointillés + flèche : utilise ou crée

Adaptater

Code de départ : ton Program.cs

  • Document est une classe concrète avec des méthodes virtual (pas une interface comme dans le cours) : écriture droite, pas d'italique.
  • AdaptateurPdf hérite de DocumentPdf et contient un ComposantPdf privé (-outilPdf, multiplicité 1) : c'est lui l'adaptateur.
  • Différence avec le cours : dans le diagramme du cours, c'est DocumentPdf lui-même l'adaptateur. Ici tu as une classe de plus, ce qui reste un Adapter.

Bridge

Code de départ : ton Program.cs

  • Deux hiérarchies : les pays (abstraction) et les technologies (implantation), reliées par le champ #implantation : le pont.
  • ControleSaisie en italique : protected abstract, redéfinie par chaque pays.

Builder (DesignPatternBuilder)

Code de départ : le Program.cs que je t'ai donné

  • Vendeur (directeur) ne dépend que du constructeur abstrait.
  • Chaque constructeur concret crée sa liasse (pointillés) et la passe au constructeur de la classe mère.

FactoryMethod

Code de départ : la version corrigée (solde, montant, acheteur)

  • La factory method CreerCommande est en italique : protected abstract.
  • Commande garde une référence vers son client (#Acheteur) : c'est ce qui permet à CommandeComptant de lire le solde.

Composite

Code de départ : la version du TD

  • Le losange côté SocieteMere : elle contient des Societe, donc d'autres mères possibles.

Decorator

Code de départ : la version du site de révision (ton Program.cs ne m'a pas été envoyé)

  • Le décorateur implémente la même interface que ce qu'il décore et en contient un seul (1 #composant).

Facade

Code de départ : la version du TD

  • Program ne parle qu'à la façade, via l'interface IWebServiceAuto (la sucette). Le sous-système ne connaît pas la façade.

FlyWeighter

Code de départ : la version du TD

  • La case nom sous la fabrique : association qualifiée, d'où le Dictionary.
  • Les paramètres position et prixDeVente d'Affiche sont l'état extrinsèque.

Prototype

Code de départ : la version du site de révision (ton Program.cs ne m'a pas été envoyé)

  • Duplique() clone le prototype ; LiasseVierge est en plus un Singleton (attribut statique souligné, constructeur privé).
Les projets marqués « version du TD » ou « version du site » ont été dessinés d'après le code du TD, pas d'après mon fichier : si ton Program.cs diffère, envoie-le et le diagramme sera refait.
